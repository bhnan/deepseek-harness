# Agent Note: 将侧边栏文件树放在设置上方

Status: proposed

[English](2026-08-28-sidebar-file-tree-footer-order.md) | 中文

## 问题

展开的侧边栏会先渲染 `sidebar.filetree` 区带，再渲染 `sidebar.footer.action`，并将 `sidebar.settings` 保持在最后。通过页脚操作 slot 添加应用快捷入口的部署因此会依次显示“文件”、应用快捷入口和“设置”。用户浏览应用目的地时，希望先看到这些快捷入口，并将文件系统工具放在固定的“设置”入口旁边。

Slot 条目的 `order` 无法表达所需排列。它只能在列表类型的 `sidebar.footer.action` slot 内排序，不能让条目跨越相互独立的 `sidebar.filetree` 与 `sidebar.settings` slot。

## 提案

展开的侧边栏将按以下顺序渲染下方入口：已注册的页脚操作、工作区文件树、设置。文件树仍是 `sidebar.filetree` 的单一占用者；页脚操作仍是 `sidebar.footer.action` 中可叠加的条目；设置仍是 `sidebar.settings` 的单一占用者。

侧边栏外壳将持有该顺序。文件树仍仅在宽态显示，高度不超过侧边栏的 40%，内部可滚动，并在没有文件树占用者时不留空隙。折叠轨道仍不显示文件树，并将页脚操作渲染在设置上方。

该变更将更新侧边栏外壳组件及样式、对应的聚焦组件覆盖、展示入口顺序的无密钥组装 Web 快照，以及双语侧边栏包文档。

## 考虑过的替代方案

**使用 slot 条目的 `order`。** 三类入口属于不同 slot，因此文件树注册项的数字顺序无法参与页脚操作排序，除非改变 slot 系统的含义。

**把文件树注册为页脚操作。** 这会让面板接收错误的 owner props 和轨道行为，把有界浏览面板混入面向行操作的列表，并废弃专用文件树 slot。

**覆盖已部署的 CSS 或 DOM。** 仅服务器生效的覆盖会偏离打包客户端，缺少仓库测试，并在下一次安装包更新时消失。

## 验收标准

- 展开的侧边栏中，每个 `sidebar.footer.action` 行都渲染在文件树面板上方，设置行渲染在文件树下方。
- 页脚操作的 `order` 仍只决定页脚操作之间的相对顺序。
- 文件树仍仅在宽态显示、可以折叠、内部可滚动、高度不超过侧边栏的 40%，并在没有占用者渲染时不留空隙。
- 折叠轨道继续将页脚操作放在设置上方，并且不渲染文件树控件。
- 聚焦侧边栏测试和无密钥组装 Web 快照固定可见顺序。
- 中英文侧边栏包文档描述变更后的放置位置。

## 风险

多个页脚操作会减少固定设置行上方的可用垂直空间。布局必须保留文件树可用的有界高度，同时防止页脚操作或面板把设置推出侧边栏。

该提案会为所有部署确定一个产品级顺序。未来如果需要按部署配置跨 slot 顺序，应单独设计带类型的布局扩展，而不是让数字顺序静默跨越 slot 所有权。
