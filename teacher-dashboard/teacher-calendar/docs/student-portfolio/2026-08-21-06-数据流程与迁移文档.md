## 1. 数据总体架构

```
┌────────────────────────────── 学生成长档案工作台（独立应用） ──────────────────────────────┐
│  录入层：手动录入 / CSV批量导入 / 表格粘贴 / 文件上传 / 自动生成（评语·分层·推送·报告）        │
│      ↓ 全部经 API（03 文档）→ 服务端校验（schema 固定 + 枚举 CHECK + 事务）                    │
│  存储层：SQLite（data/student-portfolio.db，WAL + 外键 + 唯一约束）                           │
│          + 素材文件（data/uploads/<YYYYMM>/）+ 加密字段（AES-256-GCM）+ 密钥（600）            │
│      ↓ 读取时实时聚合（不落冗余统计表，杜绝不一致）                                            │
│  计算层：学情引擎（进退步/波动/短板/班级统计）· 分层引擎 · 作业统计 · 德育汇总 · 评语/话术模板引擎 │
│      ↓                                                                                        │
│  展示层：看板 / 图表 / 时间线 / 报告 / 顶部知识卡片（轻量，形态同教学日历名言古语）          │
│      ↓                                                                                        │
│  出口层：导出（CSV/JSON/Markdown/zip）· 打印 · 备份/恢复 · 撤销/重做 · ★唯一联动→教学日历        │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```

**核心原则：单一数据源。** 所有统计、分析、报告均为查询时实时计算，不存储冗余汇总数据（唯一例外：分层快照 student_layers / layers_snapshot，因含人工微调结果，属用户数据而非纯派生）。

## 2. 数据生命周期与状态

### 2.1 各实体生命周期
| 实体 | 创建 | 更新 | 删除 | 停用 |
|---|---|---|---|---|
| 班级 | POST /classes | PUT /classes/:cid | DELETE（级联+confirm_name） | — |
| 学生 | 手动/批量导入 | PUT /students/:sid | —（不物理删除） | active=0（列表默认隐藏） |
| 考试 | POST /exams | PUT | DELETE（级联成绩） | — |
| 成绩 | batch upsert | 同 batch 覆盖 | 随考试删除 | — |
| 作业/记录 | POST/records batch | PUT/覆盖 | DELETE（级联记录） | status=closed（关闭登记） |
| 德育/特长/荣誉/素材 | 各自 POST | PUT | DELETE | — |
| 评语 | generate 生成 | PUT（saved=1） | DELETE | — |
| 分层 | layers/auto | 微调 PUT | 覆盖/撤销 | — |
| 沟通安排 | POST（自动同步） | —（改后需重同步：更新接口同步调用 sync 逻辑，本文档 3.4 定稿为「PUT 更新后 sync_status 置 pending 并自动重试同步」） | DELETE（先删日历事件） | — |
| 知识条目 | 内置种子 + 未来管理接口 | 收藏/笔记 | — | — |

> 补充约定（与 03 文档对齐）：沟通安排支持 `PUT /communications/:cid`（更新 date/time/location/note），更新后若已同步 → 先 DELETE 旧日历事件再重新 POST 同步（或调用教学日历 PUT events/:eid 更新），最终以 sync_status=synced 且 calendar_event_id 为最新事件为准。

### 2.2 撤销/重做（数据回滚）
- 写操作统一先写 undo_log（before/after 全量快照）再执行事务。
- 批量接口（import/batch/auto）整批一条 undo 记录。
- 级联删除（班级/考试/作业）在 before_json 内含级联行数组，undo 按序恢复。
- redo 栈在产生新写操作时清空。

## 3. 核心数据流程

### 3.1 成绩数据流（录入 → 分析 → 展示 → 导出）
```
表格粘贴/CSV → POST /exams/:eid/scores/batch（行级校验 + upsert + 事务）
   → exam_scores 落库
   → 读取时：
       GET /students/:sid/scores        （个人全记录，total 投影）
       GET /students/:sid/analysis      （进退步/波动/短板，引擎实时计算）
       GET /classes/:cid/analysis       （班级统计：均值/优秀/及格/分数段/进退步人数）
       GET /df/compare                  （道法跨班对比：最近同类型考试对齐）
   → 前端图表（折线/柱状/分布图）
   → 导出：CSV / 单生档案 / 评语生成的数据源
```
一致性保障：总分行与各科行在同一 batch 内原子写入；个人分析以 subject='总分' 行为基准，缺失时跳过该考试（不臆造）。

### 3.2 作业数据流
```
布置作业 POST /assignments（可选生成家长群通知话术 → 话术库）
   → 登记 POST /records/batch（每生一条，upsert）
   → 统计 GET /assignment-stats?period=（SQL 聚合：完成率/缺交/敷衍/优秀/趋势/问题学生）
   → 联动分析：个人作业态度趋势 ↔ 最近两次考试总分 delta 对照（academic_link）
```
周维度：ISO 周号 `YYYY-Www`（与日历周口径独立，纯日历周）。

### 3.3 评语生成数据流（确定性规则引擎）
```
触发 POST /comments/generate{type, period}
   → 数据装配：该生 period 内 成绩（总分序列+单科）、作业统计、德育记录、荣誉
   → 模板渲染：type=talk → 进步鼓励/退步疏导分型文案；
                type=home_school → 家校沟通框架（成绩+态度+建议）；
                type=periodic → 综合素质评语（德智体美劳五维摘要）
   → 落库 comments(saved=0) → 用户修改 PUT(saved=1) → 复用=复制到其他学生重新渲染
```
可追溯：评语由模板+数据确定性生成，同一数据快照重复生成结果一致（可复现）。

### 3.4 沟通安排 → 教学日历（唯一联动，核心状态机）
```
创建 POST /communications
   │
   ├─ calendar_link_enabled=false ──────────────► sync_status=pending（永不推送）
   │
   └─ true：学期匹配（bootstrap.semesters 按 date 命中 → 无命中用兜底学期）
        │
        ├─ 无有效学期 ──► sync_status=failed（sync_error=无法确定目标学期）
        │
        └─ POST {calendar_api_base}/api/calendar/:sid/events
             │
             ├─ 200 {event:{id}} ──► sync_status=synced, calendar_event_id=id
             │
             └─ 失败 ──► sync_status=failed, sync_error=透传
                        │
                        └─ 手动 POST /communications/:cid/sync 重试（状态机可重入）
```
```
删除 DELETE /communications/:cid
   ├─ calendar_event_id 非空 ──► DELETE 日历事件（失败不阻断，记 sync_error）
   └─ 无 ──► 直接本地删除
```
更新 PUT /communications/:cid（含 sync_status 重置）：
```
   ├─ 原 synced → 先 DELETE 旧日历事件 → 按创建流程重新同步
   └─ 原 failed/pending → 按创建流程重试
```
**联动边界（严格遵守，杜绝多余耦合）**：
- 仅此一处出站调用；不读教学日历班级/作业/考试/名言库。
- 日历事件带 `【成长档案】` 前缀（notes）与固定 color，便于用户在日历中识别与批量清理。
- 教学日历侧无需任何代码改动（events API 已存在且 CORS 已开）。

### 3.5 素材归档流程
```
上传 POST /materials（multipart）→ 校验类型/大小 → 存 uploads/<YYYYMM>/<id>.<ext>
   → event_date 推导 semester（规则 §4）→ materials 落库
   → 浏览：按 owner/category/semester 筛选；预览 GET file
   → 成长轨迹：时间线视图按 event_date 聚合
   → 导出：单素材下载 / 学期 zip 打包
```

### 3.6 顶部知识卡片流程（轻量辅助，形态同教学日历名言古语）
```
种子建库（首次启动写入四大库种子数据，见 §7 迁移）
   → 打开应用：顶部知识卡片加载当日 4 类（GET /push/today，按日期去重，全推完 round+1）
   → 卡片交互：标签切换单类（?kind=）/ 「换一条」（记录当日替换）/ 展开全文 / 收藏 / 笔记
   → 学期节点适配：按日期映射主题池优先选取
   → 轻量检索（卡片「更多」→ GET /knowledge）；复盘（设置页入口 → GET /push/review）
     ：按周/月/学期聚合推送日志+收藏笔记 → 自动成文 → 导出
```

## 4. 学期规则（固定口径，全局唯一）

| 规则 | 定义 |
|---|---|
| 秋季学期 | 08-01（新学期准备期）~ 次年 01-31 |
| 春季学期 | 02-01 ~ 07-31 |
| 学年 | 秋季学期所在自然年（2026秋 + 2027春 = 2026学年） |
| 素材归档 | 按素材 event_date 推导 `YYYY秋/YYYY春`；event_date 缺省用上传日 |
| 评语 period | 默认当前学期（按当天日期推导） |
| 复盘周期 | 周 = 最近 7 天；月 = 最近 30 天；学期 = 当前学期范围 |
| 与教学日历的关系 | 学期推导为**本应用独立口径**，仅联动时用教学日历学期列表匹配目标学期 id（两者可能不同，互不影响） |

## 5. 备份 / 恢复 / 导出流程

### 5.1 备份（POST /backup）
```
1. 开启事务读一致性（WAL checkpoint）
2. 打包：student-portfolio.db + uploads/ + manifest.json → zip
3. manifest：{app, schema_version, created_at, file_count, db_size}
4. 存放 data/backups/portfolio-backup-<ts>.zip（密钥文件不打包——密钥属本机凭据）
```

### 5.2 恢复（POST /backup/restore）
```
1. 上传 zip → 校验 manifest.app / schema_version（>当前版本拒绝，< 需迁移脚本）
2. 关闭数据库连接 → 替换 db 与 uploads → 重新打开并校验（PRAGMA integrity_check）
3. 失败回滚：保留原文件副本 data/tmp/restore-rollback-<ts>/
4. 恢复后 settings 中的 calendar_semester_id 如失效 → 置空（联动兜底自动重新匹配）
```

### 5.3 导出
- CSV：学生名单（脱敏默认）、成绩、评语（列固定，见 03 文档）。
- 单生档案：Markdown 全量（含脱敏开关）。
- 全量导出 GET /export：zip（各实体 CSV + 汇总 JSON + 素材索引）。
- 打印：浏览器 window.print()（CSS @media print 隐藏导航）。

## 6. 数据一致性保障清单（工程落地要求）

1. **schema 冻结**：schema_version=1；迁移脚本目录 `server/migrations/001_xxx.sql` 只增不改。
2. **写入单通道**：所有写操作必须经 API 层（禁止前端直连 db）；服务端统一校验（03 文档 §1.7 枚举 + 正则 + 长度）。
3. **事务边界**：单个写接口 = 一个事务；批量接口整批原子（部分失败 → 全回滚 → 返回 errors 报告）。
4. **幂等**：所有 upsert 类接口按唯一键覆盖；重复提交不产生脏数据。
5. **级联一致**：外键 ON DELETE CASCADE 兜底；删除班级等重操作在事务内先显式收集级联行入撤销栈。
6. **加密一致性**：加密仅限 10 个敏感字段；密文格式固定；密钥文件权限 600；导出脱敏规则固定。
7. **统计无冗余**：所有聚合实时计算；唯一冗余（分层快照）有 source 字段区分 auto/manual 且可整体撤销。
8. **时间一致**：全部时间戳 ISO 8601 UTC；日期 YYYY-MM-DD；前端展示本地化。

## 7. 数据迁移计划（从现有环境到本应用）

### 7.1 迁移原则
- **知识库不复用（轻量建库）**：教学日历 180 条名言古语继续留在日历（FR-6.1）；本应用四大库（教育名著精华/学段心理专项/名师实操经验/教育家金句）独立建库，种子数据随代码首发（每库首版 ≥ 20 条，共 ≥ 80 条即可——推送支持全库轮换 round+1，规模以满足一学期不厌倦为度）。
- **班级/学生不自动迁移**：唯一联动规则下两应用数据独立。首次使用通过「班级 CSV 导入 + 学生 CSV 导入」手工建库（教学日历的班级名单可从日历侧导出后复用为模板）。
- **历史成绩/德育/作业不迁移**：新应用从当前学期开始积累；如需补录历史，使用批量导入接口。

### 7.2 首次启用步骤（SOP）
```
1. 启动应用（自动建库 schema v1 + 生成密钥 + 写入知识库种子 + 默认设置）
2. 设置页：确认标题「梁老师的学生成长档案」/ 教师姓名 / 主题
3. 设置页：配置日历联动（API 地址默认 8787；测试连接；确认兜底学期）
4. 班级管理：创建主班（初一(5)班，role=homeroom）+ 代课班（各年级 role=subject）
5. 学生导入：主班 CSV（45 人全字段）→ 代课班 CSV（仅姓名/学号）
6. 成绩导入：按考试逐次 batch 录入
7. 日常使用：作业/德育/素材/评语/话术/分层/沟通安排
```

### 7.3 未来数据演进（预留）
| 场景 | 处理 |
|---|---|
| 学生毕业/升学 | 班级可标记结业（未来扩展 active 状态）；学生 active=0 保留档案可回溯 |
| 新学年 | 新建班级 + 批量导入名单；素材按学期自动归档天然分年 |
| schema 升级 | 迁移脚本顺序执行，schema_version 单调递增；备份包版本校验 |
| 教学日历升级 | 联动仅依赖 events API（03 文档 §13.4 契约）；日历若变更 events 契约，需同步升级联动适配层 |
