# Agent CLI（tc）· 意图文档（intent.md）

> 文档编号：CLI-INTENT-2026-08-27
> 流程：ai-native-sdlc 阶段 1（Plan）产物
> 提出者：梁老师；已通过澄清式提问收敛（2026-08-27 会话）
> 状态：v1.0 定稿

## 1. 背景与问题

「教师教学日历」（Express，:8787，约 60 个 REST 路由）与「学生成长档案工作台」（Express，
:8797，约 70 个路由）目前只能被 AI Agent 以"现查现拼 HTTP 请求"的方式访问：

1. **找接口成本高**：Agent 每个会话都要重新考古两端点的路径、字段名、枚举值；
2. **不一致风险高**：绕过应用语义直接构造请求（或直接改文件）容易踩坏业务规则
   （周数口径 R1、内容顺延 R3、临时调课合并 R4、成绩整批原子性等）；
3. **名称→ID 断层**：Agent 手上通常只有"初一(5)班 / 张三"，而写接口普遍要求内部 ID。

## 2. 目标用户

| 用户 | 场景 |
|---|---|
| **主**：DSH 会话中的 AI Agent | 解析/生成课表、更新学生成绩、查询学情等自动化操作 |
| 次：梁老师本人 | 终端里人工快捷操作两应用 |

## 3. 核心需求

- **R1 统一 CLI** `tc`：域分组子命令，首版覆盖 16 个高频命令（学期 2、课表/内容/docx 5、
  档案班级/学生/考试 4、成绩导入 1 含回读摘要、分析 2、发现/健康 2）。
- **R2 只经 HTTP API 写入**：业务规则校验、撤销栈、原子写入全部留在服务端；
  CLI 是纯旁路封装。默认地址 127.0.0.1:8787 / :8797，环境变量可覆盖。
- **R3 Agent 友好输出**：stdout 恒为 JSON `{ok:true,...}` 或
  `{ok:false,error:{code,message,detail}}`；人类可读诊断只走 stderr；退出码语义固定。
- **R4 内建名称解析**：学期/班级/学生/考试支持中文名模糊解析；多义返回候选清单要求消歧，绝不猜测。
- **R5 写入安全阀**：所有写命令支持 `--dry-run`；成绩导入遵循服务端整批原子语义，
  提交前本地预检姓名归属与数值合法性。
- **R6 自描述**：`tc discover` 输出全部命令的参数与示例，新会话 Agent 不读仓库文档即可用。
- **R7 DSH 原生工具注册**：`@bhn/teacher-tools` 插件把核心子集注册为本会话原生工具
  （镜像 `trading-tools` 的"CLI 为事实来源、插件仅转发"模式）。

## 4. 约束

- CLI 本体零第三方运行时依赖（Node ≥18 内置 fetch）；DSH 插件依赖与其宿主一致
  （@deepseek-ai/dsh-tools + schemastery）。
- 不重复实现引擎逻辑（周数/合并/顺延一律取自服务端端点）。
- 产物全部进版本控制（teacher-calendar 仓库），命名沿用其日期前缀习惯。
- 单机信任环境，不做鉴权；Windows 兼容不在范围内。
- 服务器迁移手册等既有部署形态不被破坏（systemd 服务不动）。

## 5. 成功标准（可验证）

- **A1 冒烟证据**：16 个命令逐一在真实服务上执行并存档输出（写命令先 --dry-run，
  再做少量真实写入并撤销回滚还原）。
- **A2 新会话盲测**：派一个全新子代理，仅凭 `tc discover` 的 JSON 完成指定任务集
  （查指定周课表 → 给某班导入一次小测成绩 → 回读该生进退步分析），全程不得查看任何
  接口文档；任务完成即通过。
- **A3 一致性验证**：构造含非法行的成绩批次验证整批拒绝且零落库；
  `docx import --dry-run` 与 `grades import --dry-run` 验证零写入。
- **A4 离线单测**：参数解析、名称消歧逻辑、CSV 长/宽格式转换的自测脚本通过
  （无网络依赖部分先行，网络部分标记跳过）。

## 6. 非目标（Out of Scope）

- **N1** 不做全量 API 覆盖：事件、生日、作业台账、德育记录、话术库、素材、备份恢复、
  道法跨班对比等低频命令缓做（discover 预留扩展说明）。
- **N2** 服务端原则上零改动；若某首版命令确需小修补（补字段/修缺陷），必须在 plan.md
  单独列出并单独审查后才允许（提出者已授权此例外通道）。
- **N3** 不做 GUI / 移动端 / 登录鉴权体系。
- **N4** 不绕过 API 直连 SQLite / JSON 存储文件读写。

## 7. 边界与异常

| # | 场景 | 行为 |
|---|---|---|
| E1 | 两服务任一不可达 | `ok:false, error.code=SERVICE_DOWN`，提示 systemd 服务与端口检查方法；不做自动重试风暴 |
| E2 | docx 解析失败（缺 python3 / 表格不合规格） | 结构化透传解析器 stderr，退出码 3 |
| E3 | 同班同名学生 / 名称命中多个班级 | 返回候选列表要求消歧，绝不猜测 |
| E4 | 周数越界 / 分数越界等服务端 4xx | 原样透传（不吞不改写），CLI 只加 code 分类 |
| E5 | 名称解析出的班级在日历侧与档案侧不同源 | 各命令声明所属应用，禁止跨应用错配；联动场景显式标注两侧 ID |
