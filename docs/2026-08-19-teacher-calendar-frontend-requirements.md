## 1. 背景与目标

在 DSH Web GUI 上以 **client plugin** 形式实现一个道德与法治（道法）教师专用教学工作日历。产品形态参考：

- 总览文档 `2026-08-19-teacher-calendar-overview.md`（六轨道需求总锚点，本文档展开轨道 F 与轨道 G 的前端呈现层）
- 交易看板插件工程 `plugins/`（host/client 半边结构与 slot 注册方式复用）

核心场景：

- **跨学段跨年级授课**：同一教师同时承担初一（初中）与小学四年级（小学）教学，需要小学/初中双独立班级预设库。
- **多班级排班备课**：5–8 个及以上班级，班级排课每周固定复用，授课内容每周独立更新，两者解耦。
- **固定课表 + 临时调课**：长期固定排课与仅当周生效的临时调课并存，互不污染；课程中间插入自动顺延、无冲突。
- **学期数据隔离**：多学期独立保存、互不覆盖、永久留存、支持历史学期回溯查看。

产品边界（沿用总览，不改变）：

- 单科专用（道法），不引入多科目切换。
- 学期视图为**事件管理型**（列表/时间线），非日历网格。
- 词库为**内置静态词库**（种子脚本生成 + 人工校订），前端只读消费。
- 仅**电脑桌面**使用；不提供移动端适配与多用户能力。

| 项 | 决策 |

## 3. 产品形态

- 载体：DSH client plugin（React，host 半边负责数据读写路由，client 半边经 slot 系统注册侧栏入口与页面）。
- **侧栏注册**：在 DSH 侧栏注册顶层入口「教学日历」（对应交易看板 slot 注册方式）。点击进入后，页面内通过**顶部页签**在周视图/月视图/学期视图间切换（G1），侧栏不再展开子菜单——三视图属于同一页面的视图层切换，非独立路由页面。
- 页面结构：

```text
教学日历（Teacher Calendar）—— 侧栏入口
└── 主工作区（单页，顶部页签切视图）
    ├── 顶部核心信息板块（全视图常驻）
    │   ├── 学期信息区（F1）：学期标准化下拉 + 学期进度条 + 当前周数
    │   ├── 今日待办任务系统（F2）
    │   └── 每日文化素养推送（F3）
    ├── 周视图（F4–F7）—— 道法教师主工作台
    │   └── 授课班级模块 / 授课内容模块（双模块解耦）
    ├── 月视图（F8/F9）—— 传统分页 / 学期全景双模式
    └── 学期视图（F10–F13）—— 事件管理型（列表/时间线 + 筛选）
```

- 布局层级（自上而下）：顶部核心信息板块 → 视图页签栏 → 视图内容区。视图内容区独立滚动，顶部板块固定常驻。
- 主题：五套主题（F14）作用于全部页面与组件，切换仅变更视觉样式，不改动数据、功能、布局、逻辑。

#### F7 调课机制（对齐总览 F7；原始需求 3.4.4–3.4.5）

| 编号 | 需求 | 说明 |
|------|------|------|
| F7.1 | 长期固定排课 | 支持**长期固定排课**：编辑固定课时可标记「固定排课」，该课每周固定复用（F4.3 班级排课模块）；修改固定排课影响后续所有周（弹窗内显式提示影响范围） |

| F7.3 | 课程智能顺延（单班内容序列） | 支持**授课内容序列顺延**（对齐总览 R3，2026-08-19 确认语义）：某班某课时内容被**替换/占用**（如改为复习、活动）后，该位置之后的**该班内容依次顺延到其后续课时位**——示例：内容序列 [一.1, 一.2, 一.3, 一.4]，第 2 节课改为「复习」→ 一.2 顺延到第 3 节、一.3 顺延到第 4 节、一.4 顺延到该班下一节课；**仅影响该班内容顺序，其他班级与课时槽位一概不动**。边界：顺延目标课时位 = 该班固定排课的下一个课时位（当天无该班后续课时则顺延到最近的下一个上课日）；顺延后提示「已自动顺延，请确认」；整条顺延链为单个原子操作，可被 G3 整体撤销；顺延超出学期范围 → 拒绝并提示（具体规则以规则护栏文档 R3 为准） |

### 4.6 全局通用功能（G1–G6）—— P0

| 编号 | 需求 | 说明 |
|------|------|------|
| G1 | 三视图自由切换 | 顶部页签提供**周视图 / 月视图 / 学期视图**一键切换，切换流畅无卡顿；切换保留当前学期与视图内浏览上下文（如聚焦日期、筛选状态，F12 除外按各自规则）；视图状态（当前学期、当前周、主题）持久化（D9） |

## 5. 非功能需求

| # | 项 | 要求 |
|---|------|------|
| 5.1 | 性能流畅无卡顿 | 三视图切换、上下周/上下月切换、主题切换均**流畅无卡顿**（目标：切换 < 200ms 感知无延迟）；周视图单周网格、月视图单月/全景网格数据量小，列表渲染直接渲染即可；长列表（事件列表 > 500 行）启用虚拟化；无重复全量重渲染（数据变更仅刷新受影响区域） |
| 5.2 | 数据持久化 | 所有数据经 host 半边读写本地 JSON 文件，**学期隔离目录**存储；**禁 localStorage 承载学期数据**（仅可承载非关键 UI 偏好兜底）；写入采用**原子写入**（临时文件 + rename，对齐 X3），崩溃不留半截文件；文件带 checksum/行数记录（X4），损坏可发现 |
| 5.3 | 错误降级 | 数据缺失/损坏时显示**占位卡**并标注缺失原因（沿用交易看板 MissingCard 模式），不静默显示空数据；Schema 校验失败时明确标注（X1：Python 写出 fail-fast + TS 读入 zod 降级），不把「无数据」当「无事件」；导入失败逐行报告原因，不整体回滚已成功行（除非用户选择全部撤销，G3） |
| 5.4 | 响应式（桌面） | **桌面优先**：最低支持 1280px 宽桌面浏览器；窗口缩放/窄屏时降级为单列布局，功能不缺失；不做移动端/触屏适配（范围外） |
| 5.5 | 数据不丢失保障 | 删除/修改/新增全部可撤销（G3）；破坏性操作（删除学期、删除班级、批量删除）二次确认；导入前强制预览；数据导出备份能力（I1 导出）作为兜底 |
| 5.6 | 主题一致性 | 五套主题下组件一致性（同组件同结构，仅视觉 token 不同）；主题切换不触发数据请求、不改变布局；默认主题保证对比度达标（文字/底色对比度 WCAG AA 级），杜绝浅淡模糊 |
| 5.7 | 日期与时间边界 | 日期计算以本机时区为准；跨年（12→1 月）、学期跨年（9.1—1.17）、闰年 2 月等边界用例正确；当日判定以自然日为准（0 点刷新今日待办与素养推送） |

## 8. 前置依赖（非前端，但阻塞前端）

1. **数据契约与 Schema 定稿**：D1–D9 + I1 字段级定义、jsonschema + zod 双端校验（X1）、fixtures（X2）——本文档 4.x 的字段细节将与其对齐回填。
2. **日历核心引擎**（`lib/calendar_core/`，纯函数）：R1 周数计算（学期总周数口径）、R6 进度计算、R3 顺延引擎、R4 临时调课合并、R5 撤销栈状态机——前端交互直接消费其输出。
3. **数据层与存储通道**：host 半边路由（P1）、学期隔离目录 + 原子写入（P2/X3/X4）；前端经插件数据接口读写，禁直接操作 localStorage。

## 9. 建议实施顺序

对齐总览 §4 决策 D5 里程碑，前端侧展开：

1. **M0 地基**：插件脚手架 + 侧栏注册 + 空页面框架；接入数据层（host 路由）与日历核心引擎（R1/R6 先落地）。
2. **M1 主工作台**：顶部板块 F1/F2（学期管理 + 进度条 + 今日待办）→ 周视图 F4/F5/F6/F7（班级库 → 双模块 → 编辑 → 调课顺延）；同步落地 G1/G2/G3/G6。
3. **M2 月视图**：F8 基础月视图 → F9 全景模式。
4. **M3 学期视图 + 全局**：F10–F12 事件体系 → F13 生日批量管理；G4/G5 补齐。
5. **M4 主题 + 导入导出**：F14 五套主题；I1 导入器接入（班级/生日/课表）。
6. **M5 打磨与验收**：非功能 5.1–5.7 逐项验收（性能、降级、边界用例），对照测试点清单回归。

> 交付硬性标准（原始需求 六）：本文档为唯一开发标准；所有功能逻辑闭环、无冲突、无 BUG、交互流畅、数据联动精准；整体适配道法教师多学段、多班级、固定课表 + 临时调课的专属教学场景。
