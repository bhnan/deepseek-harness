# 学生成长档案工作台 —— 服务器迁移手册

> 适用范围：把本机的「学生成长档案工作台」（portfolio 独立应用 + DSH 桥接插件）迁移到服务器。
> 源码根目录：`<repo>/teacher-calendar`（下称 `$REPO`）。

---

## 一、这个插件由哪几部分组成

| 部分 | 内容 | 作用 | 端口 |
|---|---|---|---|
| ① 工作台应用（本体） | `portfolio/`（Express API + Vite 前端） | 学生档案/成绩/作业台账/道法/知识库等全部业务 | API **8797**，前端 **5174** |
| ② DSH 桥接插件 | `plugins/portfolio-bridge/` | 在 DSH 侧边栏显示「📁 学生成长档案」入口，点击以 iframe 打开工作台 | 无独立端口（嵌入） |
| ③ 数据 | `portfolio/data/` | SQLite 数据库 + 素材上传 + 备份 | — |
| ④ 教学日历联动（可选） | `teacher-calendar` 主应用 | 档案内「沟通安排」→ 教学日历事件 | 日历 **8787** |

**依赖关系**：① 是核心（必须部署）；② 是 DSH 展示层（要用 DSH 才装）；④ 是唯一联动（不需要日历联动可跳过）。

## 三、服务器部署：工作台应用（①③）

### 1. 环境
- Node.js ≥ 18（推荐 20+，项目用 node:sqlite / vite）
- 生产用 `nohup`、`pm2` 或 systemd 常驻；`npm install --production` 或直接装全部依赖

### 2. 启动 API（端口 8797）
```bash
cd $REPO/portfolio
npm install                      # 安装依赖（含 esbuild、vite、xlsx、echarts 等）
# 生产启动（默认端口 8797）
node server/index.mjs
# 或用环境变量覆盖端口/数据目录
# PORT=8797 TC_DATA_DIR=/var/data/student-portfolio node server/index.mjs
```
- 首次启动会自动执行迁移（001/002…）、写入种子知识库、生成缺失的加密密钥。
- **务必把 data/ 的 `_global/portfolio_secret.json` 一起拷过来**，否则原有数据解密失败（列表脱敏显示 🔒、读取报错）。
- 自检：`curl http://127.0.0.1:8797/api/portfolio/health` → `{"ok":true,"schema_version":2,...}`

### 3. 前端（端口 5174，代理到 8797）
开发/内网：
```bash
cd $REPO/portfolio
npx vite --config vite.config.mjs     # 端口 5174
```
生产构建（把 dist/ 交给 nginx，或作为静态服务）：
```bash
npx vite build --config vite.config.mjs   # 输出 portfolio/dist/
```
> 前端会请求 `/api/portfolio/*`，需保证 5174 的代理（或 nginx 反代）转发到 `127.0.0.1:8797`。
> vite.config.mjs 已内置 proxy，开发模式直接用；生产用 nginx 时把 `/api/portfolio` 反向代理到 8797。

## 四、服务器部署：DSH 桥接插件（②）

> 若服务器上也跑 **DSH Web**（dsh 的 web 平台 profile），才需要装这个插件；否则可跳过，直接浏览器访问 `http://<服务器>:5174` 使用工作台。

### 1. 构建 + 安装（在 $REPO 执行）
```bash
cd $REPO
node scripts/build-portfolio-bridge.mjs --install
```
- 产物：`dist-bridge/@bhn/teacher-calendar-bridge/{package.json, lib/index.js, lib/client.js}`
- `--install` 会把插件复制到 **DSH profile node_modules**：
  `~/.dsh/profiles/web/node_modules/@bhn/teacher-portfolio-bridge/`

### 2. DSH 配置（cordis.patch.yml）
在 `~/.dsh/profiles/web/cordis.patch.yml` 的 `insert:` 段加入：
```yaml
- insert:
    - id: teacher-portfolio-bridge
      name: '@bhn/teacher-portfolio-bridge'
```
> 热插拔：改完刷新 DSH 页面即可（该条目可热加载，无需重启 dsh）。
> 参考本机现有配置（`~/.dsh/profiles/web/cordis.patch.yml`）中的对应段落。

### 3. 插件注意
- 插件里 iframe 指向**工作台 URL**——检查源码 `plugins/portfolio-bridge/src/index.jsx` 里嵌入的应用地址是否为 `http://<服务器>:5174`（本机为 `http://localhost:5174`），按服务器实际地址修改后重新构建。
- 插件与教学日历并列互斥（同一个时间只开一个看板），由 `dsh:overlay-open` 协议控制。

## 五、教学日历联动（④，可选）

- 工作台的「沟通安排」会自动同步为教学日历事件，通过 `calendar_api_base` 配置指向日历 API。
- 默认指向 `http://127.0.0.1:8787`（教师教学日历主应用）。
- 若迁移后需要保留联动：**必须**在服务器同时部署教学日历主应用（`teacher-calendar` 根目录，`node server/index.mjs`，端口 8787），并在工作台的「系统设置」里把日历 API 地址改成服务器实际地址。
- 若不需要联动：工作台仍可独立运行，只是沟通安排不同步日历。

---

## 六、迁移后校验清单

1. `curl http://<服务器>:8797/api/portfolio/health` → `ok:true`
2. 浏览器访问 `http://<服务器>:5174` → 学生/成绩/台账数据是否正常显示（若解密失败说明密钥没带全）
3. DSH 侧边栏出现「📁 学生成长档案」→ 点击能打开工作台
4. 如需同步：新课「沟通安排」→ 教学日历出现对应事件

---

## 七、安全提示

- `portfolio/data/_global/portfolio_secret.json` 是加密密钥，**不要**提交到公开 git；迁移用 scp/rsync 等安全通道，并限制权限（如 `chmod 600`）。
- 数据含身份证、家庭住址、家长电话等敏感信息，服务器需妥善防护（HTTPS、访问控制）。
- 备份：`portfolio/data/backups/`（也可在工作台顶栏「💾 备份」手动触发）。
