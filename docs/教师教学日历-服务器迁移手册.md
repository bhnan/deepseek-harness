# 教师教学日历 —— 服务器（云端）迁移手册

> 适用范围：把本机的「教师教学日历」主应用（teacher-calendar）迁移到云端。
> 源码根目录：`<repo>/teacher-calendar`（下称 `$REPO`）。

---

## 一、这个应用由哪几部分组成

| 部分 | 内容 | 作用 | 端口 |
|---|---|---|---|
| ① 教学日历主应用 | `server/` + `src/` | 教学日历 API + 前端 | API **8787**，前端 **5173** |
| ② 数据 | `data/` | JSON 文件存储（无 SQLite、无加密） | — |
| ③ DSH 桥接插件 | `plugins/bridge/` | DSH 侧栏「🗓 教学日历」入口，iframe 打开日历 | 无独立端口 |
| ④ 联动（与工作台） | 工作台「沟通安排」→ 日历事件 | 由工作台调用日历 API 8787 | — |

**联动方向**：学生成长档案工作台（portfolio，端口 8797/5174）的「沟通安排」会调用教学日历 API（8787）创建日历事件。
⇒ **云端要保留这条联动，必须把教学日历和工作台一起部署。**

## 二、需要拷贝的文件清单

### 必备（教学日历应用）
```
teacher-calendar/
├── server/                  # Express API（index.mjs 端口8787 / storage.mjs JSON存储 / seed.mjs / culture_data.mjs）
├── src/                     # React 前端源码
├── vite.config.js           # 端口5173、代理 /api → 8787
├── package.json
└── data/                    # ⚠️ 全部业务数据（JSON，直接拷，无密钥）
    ├── manifest.json        # 数据完整性校验清单（版本+每个文件的 sha256）
    ├── semesters.json
    ├── _global/             # classes.json / settings.json / theme.json / holidays.json / teaching_presets.json…
    ├── sem-*/               # 各学期安排数据目录
    ├── 2026-autumn-1/ 2026-spring-2/   # 按学期归档的数据目录
    └── tmp/                 # 原子写入临时目录（可建，无需拷贝）
```

### 桥接插件（DSH 部署时需要）
```
plugins/bridge/              # 教学日历桥接插件源码
scripts/build-bridge.mjs     # 构建/安装脚本（→ dist-bridge/@bhn/teacher-calendar-bridge）
```

## 三、云端部署：教学日历应用（①②）

### 1. 环境
- Node.js ≥ 18（推荐 20+）；生产用 `nohup`/`pm2`/`systemd` 常驻。

### 2. 启动 API（端口 8787）
```bash
cd $REPO
npm install
# 生产启动（默认端口 8787）
node server/index.mjs
# 或覆盖
# PORT=8787 TC_DATA_DIR=/var/data/teaching-calendar node server/index.mjs
```
- 数据是 **JSON 文件**（无 SQLite、无加密密钥），`data/` 整目录拷贝即可用，无需特殊密钥。
- 首次启动若目录有 `manifest.json` 会做完整性校验（对应文件的 sha256）；拷贝时**务必带上 manifest.json**，若校验失败会提示重新生成或重建数据。
- 自检：`curl http://127.0.0.1:8787/api/health`（健康/版本端点，路径以 index.mjs 实际路由为准）。

### 3. 前端（端口 5173，代理到 8787）
开发/内网：
```bash
cd $REPO
npx vite           # 端口 5173，/api → 8787
```
生产构建（vite build → dist/ 交给 nginx）：
```bash
npx vite build     # 输出 dist/
```
> 前端请求 `/api/*`，需保证 5173 代理（内置）或 nginx 把 `/api` 反向代理到 `127.0.0.1:8787`。

## 四、云端部署：DSH 桥接插件（③）

> 云端跑 DSH Web 才需要；否则直接访问 `http://<服务器>:5173` 使用教学日历。

```bash
cd $REPO
node scripts/build-bridge.mjs --install
```
- 产物：`dist-bridge/@bhn/teacher-calendar-bridge/{package.json, lib/index.js, lib/client.js}`
- `--install` 复制到 DSH profile：`~/.dsh/profiles/web/node_modules/@bhn/teacher-calendar-bridge/`
- `~/.dsh/profiles/web/cordis.patch.yml` 加入：
  ```yaml
  - insert:
      - id: teacher-calendar-bridge
        name: '@bhn/teacher-calendar-bridge'
  ```
- 插件源码 `plugins/bridge/src/index.jsx` 里的 iframe 地址若写死 `localhost`，需改成 `http://<服务器>:5173` 后重新构建。

---

## 五、与工作台的联动（④）

- 工作台沟通安排 → 日历事件：工作台「系统设置」的 `calendar_api_base` 默认 `http://127.0.0.1:8787`。
- 云端若保留联动：两个应用都在云端运行（日历 8787、工作台 8797/5174），并在工作台系统设置把日历 API 地址改为云端日历地址。
- 云端若不保留联动：教学日历独立运行，工作台沟通安排不同步（其余功能不受影响）。

---

## 六、云端运行顺序建议

日历（8787）与工作台（8797/5174）可独立先后启动，互不阻塞；但要联动则都需在线。
推荐启动顺序：先日历（8787）→ 再工作台 API（8797）→ 再工作台前端（5174）→ 最后（可选）DSH 桥接插件。

---

## 七、校验清单

1. `curl http://<服务器>:8787/api/health` → 正常
2. 浏览器 `http://<服务器>:5173` → 教学日历数据、学期、课程安排显示正常（若不正常，检查 manifest 是否齐全、数据目录权限）
3. DSH 侧边栏出现「🗓 教学日历」→ 点击能打开
4. （联动）工作台新建「沟通安排」→ 教学日历出现对应日历事件

---

## 八、安全提示

- 教学日历数据是**明文 JSON**（含课程、考勤/请假等），云端需 HTTPS + 访问控制。
- `manifest.json` 用于校验数据完整性，勿手动改动；迁移用 scp/rsync，保持目录结构和权限。
- 生产建议开启访问认证/内网隔离，避免日历数据接口暴露公网。
