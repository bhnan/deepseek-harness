# Intent — A 股数据访问接口

> **Plan 阶段产物（评审稿 v0.1）**，供 Design（spec.md）输入。经提出者确认后进入设计；未确认项见 §10。
> 本文件与接口契约（`docs/data-interfaces.md`，即 spec 雏形）分离管理：本文件管"做什么、怎么算做成"，后者管"接口长什么样"。

## 1. 背景与问题

- **现状**：A 股盘后数据已由每日管道落盘为 schema 校验过的 JSON 资产（`data/`）+ lab 生命周期对象（`lab/`），看板经 `/api/trading/*` 只读接口消费。
- **痛点**：Agent 做分析时要自己摸索路径、日期回退规则、symbol 规范化、聚合口径，各任务实现不一致；周期分析（周报、个股综合分析）缺乏统一、只读、可复用的数据访问层。
- **要解决的问题**：为 Agent 提供一套**一致、只读、可复用**的数据访问接口，让分析任务"取数"标准化，Agent 专注判断而非取数细节。

## 2. 目标用户

- **首选**：Agent（headless 分析/复盘任务）+ 看板前端**共用**同一套能力——**前提是零额外成本/工作量**；因此接口设计不绑定 Agent 专属形态，保持与看板能力一致。
- **兜底**：若共用会产生额外成本，则收敛为**仅 Agent 使用**。
- 说明：本条在 spec 阶段以"接口形态与现有 `/api/trading` 对齐成本"评估后最终确定。

## 3. 核心需求

### 需求一：周度趋势分析（周报）

**用户故事**：用户让 Agent 总结最近一周的市场情况。Agent 汇总一周的大盘走势、板块强弱变化、以及过去每天 Agent 自己的盘后复盘，给出"这周市场怎么样"的判断。

**素材**：
- 过去 5~7 天的大盘信息（指数、市场宽度、成交额）
- 过去 5 天的板块变化（每天前 5 / 后 5 板块、整周强弱、主线持续性）
- 过去每天的 Agent 盘后复盘（判断及其演变）

**产出**：本周综合判断——大盘演变（首尾、高低点、量能）、板块强弱与持续性、市场风格/风险演变。

**调用序列**：`dates(5) + series(index) + series(sector, top5/bottom5) + review_digest(dates)`

### 需求二：个股综合分析

**用户故事**：用户让 Agent 查看某只股票最近一段时间的表现（如"帮我看看国轩高科 `sz002074` 近期表现"）。Agent 综合该股的行情、K 线、区间高低点、相关新闻、财报、估值，判断其表现与状态。

**素材**：
- 股价 / K 线 / 区间最高最低（价格 stats + bars）
- 相关新闻 / 公告（区间内该股被提及或公告）
- 财报（最近几期利润表，PIT 时点）
- 估值（PE_TTM / PB / 总市值）
- 最新单日快照

**产出**：综合判断——价格趋势、K 线形态、消息面、基本面、估值水位。

**调用序列**：
- 一站式：`dates(5) + stock_profile("sz002074", days)`
- 分步：`series(stock, stats|bars) + stock_news + financials + valuation + stock(latest)`

## 4. 约束

- **只读**：接口只读数据，不写入任何资产（Agent 只能读）。
- **数据源**：管道每日生成的 `data/` 资产 + `lab/` 生命周期对象 + 按需导出（个股/行业/指数/聚合等权净值日线）。
- **接口形态**：⏳ **待定**（CLI / HTTP / DSH 工具），spec 阶段再定；本 intent 只定契约语义。
- **聚合口径**：统一按**加权**实现，`weights` 未指定时默认等权（已定）。
- **周期默认窗口**：`dates` 缺省 = 最近 5 个交易日（已定）。
- **兼容既有约定**：schema 校验 + manifest 完整性、源名透传 + `derived.*`、symbol 规范化（`sh/sz/bj+6位`、行业 `801xxx`）均已统一，接口承诺遵守。
- **性能**：无硬性时效指标（评审时未列入成功标准）；按需导出类操作应避免阻塞式重计算（沿用现有导出脚本的超时/缓存策略）。

## 5. 成功标准（可量化验收，经提出者确认）

1. **覆盖完整**：
   - 周报：最近 5 个交易日，4 类素材全量覆盖——指数、市场宽度、板块每天前 5/后 5、每日复盘；`period` 含首尾/高低点/持续性/regime 演变。
   - 个股分析：5 个维度全量覆盖——价格 stats、K 线 bars、相关新闻、财报、估值。
2. **口径一致**：`period` 周期指标与手工计算 / 现有逻辑比对一致（golden 用例作为对比基准，见 §9）；聚合（等权/加权净值）与现有 `aggregate` 逻辑一致。
3. **可验证**：每个接口有契约测试 + schema 校验通过；`bash scripts/run_all_tests.sh` 全绿。

> 时效（单次调用秒数）**不列入**成功标准（评审时未选择）；如后续需要再补。

## 6. 非目标（out of scope）

- **板块成分不进 universe**：板块整体用官方点位，不拆成分；成分股级明细浏览是另一场景。
- **个股专题接口（新闻/财报/估值）不做周期汇总、不通用化**：仅个股一个使用方，停留在个股级。
- **K 线不另立一族**：复用同一套 View 模型，作为 `series` 的 `mode:"bars"` 输出形态。
- **不做实时/盘中数据**：只看盘后快照与日线，不接盘中行情。
- **不做任何写能力**：无数据写入、无回测执行、无信号触发。
- **`stock_profile` 是可选便利接口**：非底层契约，纯组装层 2，Agent 可自行分步调用等价。
- **不做看板 UI 改动**：本需求只涉及数据访问接口，不涉及前端界面。

## 7. 变更面

- ⏳ **待定**（设计阶段再定）：倾向**最小侵入**——优先新增独立模块（如 `tools/` 或独立 CLI），不动现有 `pipeline/`、`host.js/route.js` 与看板；若共用方案零成本，则复用/扩展现有 `/api/trading` 逻辑。

## 8. 边界与异常

- **缺失日期**：`dates(n)` 自动跳过无数据日（以 `index_spot` 落盘为判定）；单日读取缺数据返回 `not_found`。
- **缺失字段**：返回 `null`，不得伪造、不得补默认值（如旧日期无 `amount_change_pct`）。
- **集合部分缺失**：universe 无行情标的进 `na` 计数，不参与平均，输出 `na` 名单。
- **数据损坏**：读取前做 manifest 完整性校验，不一致返回 `corrupted`，不输出半截数据。
- **越界/非法参数**：拒绝访问（403/400），仅 JSON，schema fail-fast。
- **降级原则**：任何缺失走"空态/标注"，不让 Agent 拿到带病数据。

## 9. 验证方式

1. **契约测试**：每个接口按 `schemas/` 校验输出结构；非法输入（裸代码/越界路径/非法 symbol）断言拒绝。
2. **golden 用例比对**：构造固定交易日窗口，`period` 指标与**手工计算**（或与现有 `/api/trading` 逻辑、`aggregate` 脚本）逐一比对一致。
3. **全量回归**：`bash scripts/run_all_tests.sh` 全绿。
4. **真实数据抽查**：用最近一个完整交易周的真实 `data/` 资产跑一遍两个需求的调用序列，人工核对结果合理性。
