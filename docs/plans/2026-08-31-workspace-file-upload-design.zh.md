# 工作区文件上传设计

[English](2026-08-31-workspace-file-upload-design.md) | 中文

## 目标

让 Web composer 接受拖入的非图片文件，将其存入当前工作区，并把仅路径的 `@file` 引用放入草稿，使现有 agent（智能体）文件工具可以检查它。

## 非目标

本变更不解析文档，不将文件作为多模态模型内容上传，不暴露未认证的静态文件路由，也不替换现有图片附件流程。

## 用户流程

浏览器将文件拖到现有 composer 拖放目标上，图片文件继续走当前图片附件路径，其他文件则通过工作区上传 RPC 发送。

Host 解析已认证的 Workspace id，将文件写入 `<workspace>/uploads/` 下，并返回相对路径和基础元数据。

Composer 在当前草稿光标处插入类似 `@uploads/report.pdf` 的安全仅路径引用；普通 prompt 提交会记录这段文字，是否以及如何读取或解析文件由 agent 决定。

## Host 边界

Workspace API 增加 `workspace.uploadFile`，本地 v1 使用已有的认证 JSON RPC 载体和有上限的 base64 载荷。

请求携带 `workspaceId`、浏览器 `name`、可选 `mediaType` 和 base64 `data`；响应携带工作区相对 `path`、存储后的 `name`、字节数、SHA-256 摘要和可选媒体类型。

Host 将文件存入专用的 `uploads/` 目录，以私有权限创建该目录，清理文件名中的路径分隔符和控制字符，拒绝空文件名或超大载荷，并绝不跟随 `uploads` 符号链接。

不同内容发生文件名冲突时使用确定性的短摘要后缀；相同内容的已有上传会复用。返回路径始终相对于工作区根目录，并使用 `/` 分隔符。

默认单文件上限为 32 MiB。这个上限有意适配当前 JSON 传输，为本地功能提供清晰边界；未来的流式 multipart 路由可以提高上限，而无需改变工作区相对路径响应约定。

端点依赖部署已有的 API 认证／信任包装。它不增加公开下载路由；已有的 agent 文件系统能力仍然是唯一的文件内容访问路径。

## Client 边界

Conversation composer 的附件持有方同时接受图片添加回调和工作区文件上传回调。文档级拖拽监听器按 MIME 类型分流混合拖放，因此图片准入与文件持久化彼此独立。

Conversation bar 根据当前会话的 Workspace 成员关系解析当前工作区，为每个非图片文件调用 `workspace.uploadFile`，并使用当前草稿快照插入返回的引用。上传失败通过现有 composer toast 显示，且不改变草稿。

现有图片预览、图片限制、图片准入和仅图片模型载荷保持不变。

## 验证

Host 单元测试覆盖 base64 校验、文件名／路径安全、大小限制、私有上传目录、确定性冲突命名和返回相对路径。

RPC 测试覆盖请求与响应 schema、认证载体分发、未知 Workspace 处理以及无效上传返回的业务错误。

Client 测试覆盖混合拖放分流、上传回调调用、成功插入路径、失败时保留草稿和未改变的图片流程。

Web bundle 与包检查在聚焦测试之后运行；本地手工验证使用独立工作树和临时工作区，不使用用户的 `feat/workspace-file-tree` 主工作树。

## Docker 影响

镜像需要源码或构建后的包以及 Web bundle，运行时容器必须持久化 DSH home 和所有配置的 Workspace 目录。上传文件是这些工作区挂载下的普通文件，因此只要保留 volume 映射，替换容器也会保留文件。
