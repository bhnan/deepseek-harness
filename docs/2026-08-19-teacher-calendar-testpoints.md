# 教师教学工作日历测试点清单

日期：2026-08-19
状态：v1。配合总览文档 `2026-08-19-teacher-calendar-overview.md` 使用；测试点编号与需求编号一一对应（F1–F14 / G1–G6 / D1–D9 / I1 / R1–R7 / C1–C3 / P1–P4 / X1–X4）。

## 0. 测试哲学

1. **验证系统正确性，不验证教学内容正确性**：词库词条（教育古语/诗词/理念）的内容优劣是内容问题、不是测试问题；测试对象是"推送机制能否按规则无重复、按状态更新地分发词条"，以及"日历引擎能否正确执行任意已录入的教学安排"。
2. **日历核心引擎定位 = 纯函数库，是测试主战场**：周数计算（R1）、学期联动（R2）、顺延（R3）、临时调课合并（R4）、撤销栈（R5）、进度计算（R6）、生日展示位判定（R7）全部是无副作用的纯函数，喂入确定输入必须得到确定输出，可逐条断言。
3. 框架：Python 用 pytest（引擎 + 数据层/schema 校验）；前端用 Vitest + React Testing Library（三视图/顶部板块/主题/事件管理组件）。框架选择服从"能在 DSH 插件开发流里跑"（作为 bash 可执行脚本，agent 会话可触发、结果可查）。
4. 测试点写法约定：每条 = 喂什么输入 → 断言什么输出/行为。

## 1. 按需求的测试点

### 轨道 F：视图与功能（前端页面）

| 需求 | 测试点 |

### 轨道 R：核心业务规则引擎（日历正确性护栏，测试主战场）

> 注：总览 §2.1 标注规则护栏文档 `2026-08-19-teacher-calendar-rule-spec.md` 定稿，但磁盘上暂未见该文件；下列测试点按总览 §1 轨道 R 定义 + 本清单撰写，文件落盘后需与该文档验收标准逐条核对映射（见 §4）。

| 需求 | 测试点 |
|------|--------|
| R1 周数计算 | ① 输入 2026-08-25（开学 09-01 前）→ 断言不显示周数、不提前计数（返回未开始）；② 输入 2026-09-01（开学当天）→ 断言 = 第 1 周；③ 输入 2026-09-08 → 断言 = 第 2 周（顺次累加）；④ 输入 2026-12-29（第 18 周）与 2027-01-05 → 断言跨年周数连续递增、不重置；⑤ 同一日期分别调用周视图/月视图周次栏/学期视图所用计算函数 → 断言输出同一周数（全站统一"学期总周数"口径，禁月度周数） |
| R2 学期联动 | ① 新建"2026秋季第一学期" → 断言自动带出绑定日期 09.01-01.17；新建"2027春季第二学期" → 断言带出 02.22-07.06（名称-日期绑定表）；② 编辑 2026秋 起止为 09.07-01.24 → 断言周数（R1）、进度（R6）实时联动更新；③ 删除学期 → 断言关联数据处理符合 G6 隔离规则、其他学期不受影响 |
| R3 授课内容序列顺延 | ① 将某班第 2 课时位内容替换为「复习」→ 断言该班内容序列变为 [一.1, 复习, 一.2, 一.3]，一.4 顺延至该班下一课时位（链式后移，SH2）；② 其他班级内容序列与当日课时槽位 → 断言 unchanged（仅该班序列变动，SH1/SH6）；③ 顺延目标课时位被临时调课占用 → 断言按 C2 规则继续后移找空位或整次拒绝（原子，无半状态，SH4/SH5）；④ 顺延超出学期末 → 断言整次替换被拒绝、原序列保持原样（SH7）；⑤ 删除该班第 2 课时位内容 → 断言第 3 课时位不前移补位（留空档，SH8） |
| R4 临时调课 | ① 本周发起临时调课 → 断言本周课表已合并生效；② 切到下周 → 断言恢复固定课表原样（仅当周生效）；③ 临时调课与固定课程同时段 → 断言临时调课优先展示、固定课表文件不被修改（叠加规则）；④ 调课前后的 fixed_course.json → 断言 checksum 不变（固定排课长期复用） |
| R5 撤销栈 | ① 连续 delete→edit→add 三步 → 断言栈深 3、按 LIFO 撤销顺序正确；② 撤销 2 步后点恢复 → 断言重做正确（恢复语义）；③ 操作后重启 → 断言撤销栈从 D9 settings 持久化恢复、可继续撤销；④ 撤销删除课程 → 断言该课程引用（班级/内容）仍有效、无悬空引用（引用完整性） |
| R6 进度计算 | ① 2026秋（09.01-01.17），输入 2026-10-13 → 断言 progress = (当前-开学)/(放假-开学) 的手工计算值（公式断言）；② 开学当天 → 断言 0%；放假当天 → 断言 100%；③ 学期中点前后两天 → 断言进度单调递增；④ 修改起止日期 → 断言进度实时更新（R2 联动） |
| R7 生日展示规则 | ① 某日有生日 → 断言生日仅出现在周视图顶部星期日期栏 + 月视图轻提醒，共 2 处（唯一展示位）；② 生日当天有课 → 断言课程单元格不显示生日信息（课时区禁重复）；③ 当天无生日 → 断言无任何生日展示 |

### 轨道 C：内容库（每日文化素养推送）

| 需求 | 测试点 |
|------|--------|
| C1 词库结构 | ① 合法词条（五类之一 + 原文 + 白话翻译 + 通俗释义 + 标签）→ 断言通过 culture_entry.json 字段完整校验；② 缺任一字段 → 断言被拒且错误含字段路径；③ 类别越五类枚举 → 断言被拒 |
| C2 推送算法 | ① 每日自动触发 → 断言推送 1 条且 push_state 当日记录正确；② 手动刷新 → 断言换一条且与当日已推送不重复；③ 连续推送 ≥ 词库规模 → 断言全库无重复（去重保证）；④ 轮换耗尽后刷新 → 断言行为符合内容库规范 §3 定义（重置/标记，不静默重复）；⑤ 跨学期 → 断言按规范跨学期规则处理（F3 联动） |
| C3 词库可维护性 | ① 新增词条 → 断言通过校验并入推送池；② 删除/修改词条 → 断言推送去重计数联动正确、已推送历史不受影响 |
