# 教师教学工作日历 —— 核心业务规则边界与护栏设计（验收规格）

日期：2026-08-19
状态：v1。定位：轨道 R（R1–R7 业务规则引擎）的**需求规格与验收标准**，是日历核心引擎（总览 §2.4 待建产出 ③ `lib/calendar_core/`）的验收门槛。任何实现（自建或复用）未通过本规格护栏的，**结果作废**。

术语约定（全站统一，本文档各处同义）：**学期总周数**（全站唯一周数口径，禁月度周数统计逻辑）；**固定排课**（每周复用的固定课程模板，含授课班级/时段）/**临时调课**（仅当周生效）；**授课班级/授课内容**（双模块解耦，班级排课每周固定复用、内容每周独立更新）；**链式后移**（内容替换后，该班后续授课内容依次后移一个课时位的动作）。

## 1. 问题定位

日历系统的正确性风险集中在**边界处理**，而不是渲染能力——画 30 天网格、画进度条不是问题；周数多算一周、顺延链断在半路、临时调课泄漏到下一周才是问题。错误类型六类：

| 错误类型 | 典型表现 | 后果 |
|---------|---------|------|
| 周数口径错误 | 开学前显示周数/倒计数、跨年周归零重数、各视图周数不一致 | 周视图/月视图/顶部互相矛盾，教师备课错位 |
| 学期日期越界 | 课程/事务落在学期范围外仍显示、编辑起止日期后派生值不联动 | 周数、进度、视图与真实学期脱节 |
| 顺延链断裂/冲突 | 内容替换后该班后续内容未全部链式后移、或顺延落位撞课 | 该班内容序列错乱，教学进度脱节 |
| 临时调课泄漏到其他周 | 当周调课下周仍生效、或反向污染固定排课模板 | 固定课表被静默篡改，跨周不一致 |
| 撤销栈与数据不一致 | 撤销后出现半状态（班级已删课程残留）、重启后栈失效 | 数据丢失/悬空引用，防丢失机制反成破坏源 |
| 生日重复展示 | 生日姓名出现在课时区域、遮挡课程/事务内容 | 违反 R7 唯一展示位规则 |

**开工警示**：当前引擎实现为 0（总览 §3「日历核心引擎 ░ 0%」）。本规格先行于实现，禁止"先写 UI、后补规则"的反向路径——UI 只消费引擎输出（§3.1），引擎行为以本文档 §2 为唯一标准。

## 2. 边界全景与护栏（验收清单）

### 2.1 周数计算类（R1）

| # | 边界 | 具体问题 | 护栏要求 | 涉及需求 |
|---|------|---------|---------|---------|
| W1 | 开学前不计数 | 查询日期早于开学日时显示周数或出现倒计时式周数 | `week_of(semester, date)` 对 date < 开学日 一律返回"未开学"（不显示周数、不提前计数）；全站无任何倒计时周数 | R1 |
| W2 | 第1周定义 | 开学日所在周的归属口径不一（开学日恰逢周中，周内开学前的日子算第几周？） | 第1周 = 开学日所在周（周一起始，与 F8 月视图表头周一至周日一致）；该周内早于开学日的日子按"未开学"显示；开学日当天起显示"第1周" | R1/F8 |
| W3 | 跨年周 | 学期跨 12/31（2026.09.01–2027.01.17），周数在年初清零重数 | 周数自开学日连续累加，跨年不重置：第N周 = floor((date − 第1周周一)/7) + 1（date ≥ 开学日） | R1 |

| W5 | 周数与日期映射 | 周内任意日期→第几周的双向映射漂移（同一日既算第X周又算第X+1周） | 映射为确定性纯函数：同一天在全站任何视图返回同一周编号；覆盖开学前/开学日/跨年/期末四个时点测试（见 §4 第 1–3 条） | R1 |

### 2.3 授课内容序列顺延类（R3）—— 单班内容序列顺延（2026-08-19 用户确认语义）

> **语义确认**：顺延是**单个班级授课内容序列**的顺延（D4 内容层），**不是**当日课时槽位轴的整体移动。示例（用户原例）：某班内容序列 [一.1, 一.2, 一.3, 一.4]（第一课第 1–4 课时，按该班上课时间排序，可跨天/跨周分布），第 2 节课内容改为「复习」→ 期望结果：一.2 顺延到第 3 节课的位置、一.3 顺延到第 4 节课的位置、一.4 顺延到该班下一节课。**只影响这一个班的内容顺序，其他班级、课时槽位、固定排课模板一概不动。**

| # | 边界 | 具体问题 | 护栏要求 | 涉及需求 |
|---|------|---------|---------|---------|
| SH1 | 顺延对象与维度 | 把"顺延"误解为课时槽位轴的整体移动（把其他班的课挤到下一时段） | **顺延作用于单个班级的授课内容序列**（D4 内容层），不是课时槽位（D3 固定排课）轴；一次顺延只重排该班的内容序列，其他班级内容、当日所有课时槽位位置均不变 | R3/D4 |
| SH2 | 顺延触发与效果 | 被替换位置之后的内容如何处理 | 某班某课时内容被**替换/占用**（改为复习、活动、临时插入内容）→ 该位置之后的内容**依次后移一个课时位**（链式后移）：示例 [一.1, 复习, 一.2, 一.3]，一.4 顺延至该班下一课时；被替换位置本身保留新内容，不产生空位 | R3/D4 |
| SH3 | 顺延目标课时位 | 被顶出的内容移到哪个课时 | 顺延目标 = **该班固定排课中的下一个课时位**（该班下一次上课时刻）；当天无该班后续课时 → 顺延到该班最近的下一个上课日（可能跨周）；目标课时位确定规则见待确认 C2 | R3/D3/D4 |
| SH4 | 链式顺延与原子性 | 一次替换只动一格还是整条链；链中断在半路 | 整条顺延链为**单个原子操作**（X3）：自替换位置起该班后续内容依次后移，任何一环无法落位（目标课时位被临时调课占用且无法再后移、超出学期末）→ 整次替换不生效（原子失败），提示用户，不留半状态 | R3/R5/X3 |
| SH5 | 冲突检测 | 顺延目标课时位已被临时调课/活动占用 | 顺延链冲突预检：目标课时位被**临时调课**占用 → 顺延目标继续后移找空位（建议，见待确认 C2）；临时调课本身不参与顺延、不被顺延移动（TM3） | R3/R4 |
| SH6 | 顺延范围边界 | 顺延是否会波及同一天其他班级 | **仅该班**：其他班级的内容序列、课时槽位、固定排课模板一概不动；同一日其他班的课不受任何影响 | R3/D4 |
| SH7 | 学期末越界 | 顺延链超出学期最后一个课时位 | 顺延超出学期末 → 整次替换拒绝（原子失败）并提示"内容顺延超出学期范围"；被顶出且无处安放的内容保留在"待安排"提示中，不静默丢失（处置规则见待确认 C3） | R3 |
| SH8 | 删除内容后的行为 | 删除该班一课内容后，后续是否前移补位 | **建议：删除不反向补位**（内容序列保持原课时位，留出空档由用户自行安排）；反向补位为备选，见待确认 C5；删除可撤销（R5） | R3/G2 |

### 2.5 撤销/恢复类（R5）

> 事务性保证（总览 R5 注"事务性保证见规则护栏"）：单次用户操作 = 单个原子提交（X3），撤销/重放同样按原子提交执行（UN6）。

| # | 边界 | 具体问题 | 护栏要求 | 涉及需求 |
|---|------|---------|---------|---------|
| UN1 | 栈语义 | 撤销/恢复的方向与范围不一致 | 单栈模型：新操作入栈顶；撤销 = 取栈顶逆操作重放并移入恢复栈；恢复 = 取恢复栈顶原操作重放回主栈；增/删/改/批量/导入跨操作类型统一入栈 | R5/G3 |
| UN2 | 可撤销操作范围 | 哪些操作可撤销、哪些不可 | 全部用户写操作可撤销：单条增删改、右键删除（G2）、批量导入/批量删除（G4/I1）、编辑学期起止日期；时间驱动的自动行为（临时调课下周自动失效、进度变化）不入栈、不可撤销 | R5/G2/G3/G4 |
| UN3 | 撤销后引用完整性 | 撤销后出现"班级已删、课程残留"或"课程引用已删班级" | 级联操作作为**单个栈项**：删除班级 = 班级 + 其固定排课 + 授课内容，一次撤销全部还原；任何时刻数据满足引用约束（课程→班级、事件→学期），校验见 CS4 | R5/X1 |
| UN4 | 栈持久化与重启恢复 | 重启后撤销/恢复不可用或栈错乱 | 栈随学期持久化（settings 运行态字段，字段以 schema 文档为准，总览 D9）；栈写入与数据变更同一原子提交（X3），重启后栈完整可用；**栈按学期隔离**，切换学期不串栈 | R5/D9/X3/G6 |
| UN5 | 栈深度上限 | 栈无限增长内存膨胀、或超限后行为未定义 | **建议上限 100 步**（见待确认 C6）；超限淘汰最旧项；每条栈项为自包含逆操作，淘汰不破坏其余项 | R5 |
| UN6 | 事务性 | 撤销/重放中途失败导致数据半状态 | 每次操作（含撤销/重放）为单个原子提交（X3 临时文件+rename）；失败则数据保持操作前状态并报错，不允许半截状态落盘 | R5/X3 |

## 3. 结构性护栏（架构而非文档约定）

### 3.1 日历核心引擎 = 纯函数库

```text
lib/calendar_core/                      （总览 §2.4 待建产出 ③；纯函数、无 IO、无 UI）
    week_of(semester, date)             → {status: "未开学"} | {status: "第N周", week, total}
    semester_total_weeks(semester)      → 学期总周数（全站唯一口径，W4）
    progress(semester, today)           → 0..100（口径见待确认 C1）
    shift_content(class_content_seq, pos, new_content) → 新序列 | 拒绝（越界/冲突，原子失败）
    merge_week_view(fixed_template, temp_changes, week) → 当周合并视图（临时调课优先，TM2）
```

> `shift_content` 输入 = 某班级的授课内容序列（按该班上课时间排序）+ 替换位置 + 新内容；输出 = 链式后移后的新序列（SH2/SH4）。顺延只作用于内容序列（D4），不触碰课时槽位（D3）与其他班级（SH1/SH6）。

- 引擎不持有状态、不读写文件：输入为校验过的域对象，输出为不可变结果；
- UI（三视图/顶部板块/今日待办）只消费引擎输出，禁止在组件内自行实现周数、顺延、合并逻辑；
- 引擎行为以本规格 §2 为唯一标准，实现可替换（换语言/换库）而不改变验收结果。

### 3.2 派生值实时计算、不落库

- 周数、学期总周数、进度百分比为**派生值**：由学期起止日期 + 当前日期实时计算，不写入任何数据文件；
- 唯一按需持久化的运行态：撤销栈（settings，D9，见 UN4）；临时调课的"生效周"是真实数据而非派生值；
- 禁止把派生值缓存进文件（防"缓存过期 ≠ 数据过期"类 bug）。

### 3.3 引擎输入输出全走 schema 校验

- 引擎入参先过 X1 校验（Python jsonschema fail-fast / TS zod 降级）再进入纯函数；
- 引擎返回值按固定结构返回（§3.1 签名），UI 端按契约消费（X2 fixtures 覆盖合法/非法样例）；
- 校验失败即拒绝操作并提示，不允许半结构化数据进入计算链。

## 4. 验收标准清单（每条可测试）

格式：给定输入 → 断言输出。被测对象为 §2 护栏与 §3 引擎接口。

1. 给定学期 2026.09.01–2027.01.17，查询 2026.08.25 → 返回"未开学"，不显示周数；查询 2026.08.31（开学前一日）→ 仍"未开学"；查询 2026.09.01 → "第1周"。
2. 同上学期，查询 2026.12.28 → "第18周"；查询 2027.01.04 → "第19周"（跨年周连续累加、不归零）；查询 2027.01.17 → "第20周"。
3. 给定学期 2027.02.22–2027.07.06 → 学期总周数 = 20，与 2026 秋季（09.01–01.17）同为 20 周；周视图、月视图、顶部三处显示同一总周数（同一引擎函数，W4）。
4. 给定某班授课内容序列 [一.1, 一.2, 一.3, 一.4]（按该班上课时间排序），将第 2 个课时位内容替换为「复习」→ 断言序列变为 [一.1, 复习, 一.2, 一.3]，一.4 顺延至该班下一课时位（链式后移，SH2）；其他班级内容序列与当日课时槽位不变（SH1/SH6）。
5. 顺延目标课时位已被临时调课占用（按 C2 建议"继续后移"）→ 断言顺延链继续后移直至空位；若整条链任何一环无法落位（含超出学期末）→ 断言整次替换被拒绝、原序列保持原样（原子失败，SH4/SH5/SH7）。
6. 删除某班内容序列中第 2 课时位的内容 → 断言第 3 课时位不前移补位（留空档），其余位置不变（SH8）。
7. 第 5 周创建临时调课覆盖周一 10:00 固定课程 → 断言第 5 周视图显示调课内容、固定排课数据未变；第 6 周视图恢复原固定排课（自动失效，TM1/TM2）。
8. 删除某课程 → 撤销 → 断言课程恢复且时段位置、授课班级、授课内容引用完整；再恢复 → 断言再次删除生效（UN1/UN3）。
9. 学期 A 执行 3 步操作后切换到学期 B 执行 2 步，再切回 A → 断言 A 的撤销栈仍可连续撤销 3 步（栈按学期隔离，UN4）。
10. 周视图存在生日姓名 → 断言该姓名仅出现在顶部星期日期栏，课时单元格内无该姓名文本（RD1）。
11. 给定学期 2026.09.01–2027.01.17（自然日 139 天，含首尾），progress(2026.09.01) = 1/139、progress(2026.09.15) = 15/139 ≈ 10.8%、progress(2027.01.17) = 100%；开学前 = 0%、结束后 = 100%（C1 确认后按最终公式断言，SM5）。
12. 模拟写入中途崩溃（kill 进程）→ 重启后学期文件为完整旧版本或完整新版本，无半截文件；checksum 校验通过（X3/X4，CS2/CS3）。
